# Private Aufgaben

Diese Seite beschreibt eine Methodik zur Verwaltung privater Aufgaben über GitHub. Kurz gesagt, es funktioniert wie folgt:

1. Jede Aufgabe ist ein **privates Repository** unter dem Teilnehmerkonto; wo der Lehrer **Mitarbeiter ** Zugriff erhalten hat.
2. Der Schüler leistet seine Arbeit in einem **Zweig** und gibt seine Arbeit zurück, indem er eine **Pull-Request** mit dem Lehrer als **Reviewer** erstellt.

Diese Methode ist der Art und Weise, wie professionelle Entwickler GitHub verwenden, sehr ähnlich.

### ~hint

#### Öffentliche Repositories

Die Verwendung von **public** Repositories vereinfacht die Konfigurationsphase für die Zuweisungen. If it is acceptable for the code to be publicly available on [GitHub](https://github.com), we recommend using the [public assignments](/github/public-assignments).

### ~

## Schritt 1: Schüler erstellen ein neues privates Repository

Mit dem MakeCode-Editor erstellt der Schüler ein **privates** Repository für die Zuordnung, die unter seinem Konto gehostet wird (**Stelle sicher, dass du privat wählst!**). Alle Schüler sollten das Projektarchiv mit dem Aufgabennamen benennen (z.B. "Hausaufgaben" in diesem Beispiel).

### Schritt 2: Schüler laden Lehrer als Mitarbeiter ein

Der Schüler muss den Lehrer als **Mitarbeiter ** einladen.

* öffne die **Mitarbeiter ** Seite mit dem Knopf Mitarbeiter
* Gebe den Lehrer-Alias in das Textfeld ein und sende die Einladung.
* der Lehrer muss die Einladung annehmen, um Zugang zum privaten Repository zu erhalten

![Screenshot der Mitarbeiterseite auf GitHub](https://makecode.com/not-found/HEAD/static/github/classroom/addcollaborator.png)

### ~hint

#### GitHub und 404

Wenn du den Einladungslink ausprobierst und du einen **404** Fehler bekommst bedeutet dies höchstwahrscheinlich, dass du nicht bei GitHub angemeldet bist.

![GitHub 404 Seite](https://makecode.com/not-found/HEAD/static/github/classroom/404.png)

### ~

## Schritt 2: Schüler Änderungs-, Commit-, Push-Zyklus

Es ist Zeit zu arbeiten! Schüler können all ihre Arbeit erstellen und die **commit & Taste drücken** benutzen, um sie zu speichern. Es ist eine gute Idee, sie dazu zu ermutigen, einen Commit auszuführen, wenn sie das Gefühl haben, dass bedeutende Fortschritte gemacht hat. Stellen Sie sicher, dass sie eine aussagekräftige Beschreibung der Änderungen für die Übertragung liefern.

## Schritt 3: Der Lehrer überprüft den Commit-Verlauf

Der Lehrer kann den [MakeCode GitHub Explorer](https://makecode.com/github-explorer) verwenden, um einfach die Repositories eines Benutzers zu durchsuchen. Bei Bedarf kann der Lehrer auch den gesamten Verlauf des Projekts auf GitHub einsehen.

## Schritt 4: (optional) Schüler macht das Repository öffentlich

Wenn die Schüler dieses Projekt ihrem Portfolio hinzufügen möchten, können sie es einfach öffentlich machen und es wird auf ihrer GitHub-Benutzerseite sichtbar sein.
