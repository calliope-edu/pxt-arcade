## Quels sites web dois-je débloquer pour Arcade ? #unblock

L'accès à certains domaines est nécessaire pour que l'éditeur web puisse atteindre toutes les ressources dont il a besoin pour fonctionner pleinement. Voici les domaines que tu dois débloquer :

* https://arcade.calliope.cc
* https://makecode.com
* https://trg-@targetid@.userpxt.io
* https://cdn.makecode.com
* https://api.github.com
* https://immersivereaderprod.cognitiveservices.azure.com

Pour activer des fonctionnalités supplémentaires pour le développement, les domaines suivants sont également nécessaires. Dans la plupart des cas, il n'est pas nécessaire de débloquer ces domaines :

* https://github.com
* https://raw.githubusercontent.com/

## Où mes projets sont-ils enregistrés ?

Les projets sont conservés dans la mémoire locale du navigateur. Tu peux enregistrer ton projet avec un nom. Si tu ne donnes pas de nom à ton projet, il est conservé comme projet « Sans titre ». Tu peux aussi enregistrer ton projet dans un fichier ou dans le cloud.

Pour en savoir plus, consulte la page sur l'[enregistrement](/save) des projets.

## Puis-je utiliser MakeCode sans être connecté à Internet ? #work-offline

Certains éditeurs MakeCode sont disponibles sous forme d'[applications hors ligne](/offline). Quand MakeCode est chargé pour la première fois dans le navigateur, une version en cache est enregistrée automatiquement. Si tu veux ajouter plus tard une extension à ton programme, tu devras te reconnecter. Pour en savoir plus, consulte la page sur l'utilisation de MakeCode [hors ligne](/offline).

## Puis-je utiliser des extensions sans être connecté à Internet ?

Oui, il est possible d'enregistrer des extensions pour que tes programmes puissent continuer à les utiliser hors ligne. Suis [ces instructions](/offline#extensions).

## Que se passe-t-il si je vide le cache et les fichiers temporaires du navigateur ? #clear-data

Si tu effaces les données du navigateur, tous les projets enregistrés et les fichiers dont MakeCode a besoin hors ligne sont supprimés. Les projets que tu as partagés dans le cloud public sont toujours là.

## Où va un projet que je partage ? #sharing

Quand tu partages un projet, il est enregistré dans le cloud public. Toutes les personnes qui ont le lien du projet peuvent le voir.

## De quelles autres façons puis-je partager des projets avec mes enseignants et mes amis ? #share-options

* Utilise le bouton Partager pour publier ton projet dans le cloud. Tu peux envoyer le lien de partage à n'importe qui.
* Le lien de partage peut être collé dans une page OneNote ou intégré comme lien sur un site web. Dans certains cas, le lien est automatiquement transformé en un aperçu de ton projet en lecture seule.
* Tu peux enregistrer le projet et le copier sur le site web de la classe ou dans un emplacement autorisé du réseau de la classe ou de l'école.
* Tu peux copier du code et le coller dans la vue JavaScript de l'éditeur. Cela te permet de déplacer du code entre MakeCode et d'autres applications sur ton ordinateur ou ton appareil.

## Pourquoi l'éditeur utilise-t-il encore l'ancien nom du projet alors que j'ai renommé le fichier téléchargé ?

Quand tu télécharges le programme de ton projet, le nom du projet fait partie du fichier téléchargé. Si tu renommes le fichier téléchargé, l'éditeur continue d'utiliser et d'afficher le nom que tu as choisi pour le projet, et non le nom actuel du fichier.

## Je viens d'ajouter / d'approuver une nouvelle traduction dans Crowdin, quand apparaîtra-t-elle ?

Les [traductions](https://makecode.com/translate) sont gérées sur le site [Crowdin](https://crowdin.com/project/makecode). Un processus planifié vérifie régulièrement les nouvelles traductions dans Crowdin et les publie sur le site qui héberge un éditeur MakeCode. Il faut en général 10 à 30 minutes entre l'approbation d'une nouvelle traduction et son apparition dans un éditeur en ligne.

## Où est le bouton « Ajouter un paquet » ?

Les paquets ont été renommés **Extensions** pour correspondre aux autres éditeurs de code. Tu trouveras maintenant le menu **Extensions**, qui remplace le bouton **Ajouter un paquet**.

## Comment puis-je partager des tutoriels ? #share-tutorials

Les tutoriels se chargent dans l'éditeur, ce qui peut les rendre difficiles à partager. Si tu veux créer un lien direct vers un tutoriel, tu dois trouver l'emplacement du tutoriel dans la documentation de la cible. À partir de là, tu peux créer un lien qui mène directement au tutoriel. Par exemple, pour créer un lien vers le tutoriel `Cœur clignotant` du micro:bit, tu dois…

1. Trouver le tutoriel dans la documentation : <https://makecode.microbit.org/projects/flashing-heart>.
2. Prendre cette URL et la séparer en deux parties : le domaine principal (`https://makecode.microbit.org`) et l'emplacement du tutoriel (`/projects/flashing-heart`).
3. Insérer `/#tutorial:` entre ces deux parties : <https://makecode.microbit.org/#tutorial:/projects/flashing-heart>.

Si tu regardes le dépôt GitHub de la cible, le lien a cette forme :

    https://[url de l'éditeur]/#tutorial:/[emplacement du tutoriel dans le dossier docs]
    

Si tu veux créer ton propre tutoriel, tu trouveras [ici](https://makecode.com/writing-docs/user-tutorials) plus de documentation.

## Comment choisir le dossier où sont enregistrés mes projets téléchargés ?

Dans la plupart des navigateurs, tu peux activer un réglage pour que le navigateur te demande où enregistrer tes fichiers avant de les télécharger.

* Dans Microsoft Edge, ouvre le menu du navigateur et choisis **Paramètres**. Dans la section « Général », fais défiler jusqu'à la section **Téléchargements**. Active le réglage « Demander quoi faire avec chaque téléchargement ».
* Dans Chrome, va dans **Paramètres** depuis le menu du navigateur. Sur la page des paramètres, clique sur **Avancés** pour afficher plus de réglages. Dans la section **Téléchargements**, active le réglage « Demander dans quel dossier enregistrer chaque fichier avant de le télécharger ».
